# التحدي القرآني — QuranGames

نسخة موسّعة 0.2 قابلة للتجربة، بتاريخ ١٧ أكتوبر ٢٠٢٦. الهوية مبنية على ألوان الصورة المعتمدة: الأزرق `#3368A0`، الأزرق الهادئ `#66A3BF`، النعناعي `#C8DFDB`، الكريمي `#F2EFE7`، مع البترولي `#174C46` والزيتوني `#76834A`.

## جديد الإصدار 0.2

- منع تكرار الأسئلة الجديدة بسجل دائم على الجهاز، ومعاملات حجز سحابية للعضويات بعد الربط. لا تُعاد الأسئلة عند تغيير الصعوبة أو إغلاق اللعبة.
- ٦١٢٢ موضعًا لسؤال الآية التالية، و٥٧٧٩ سؤال استرجاع كلمة، و٥٩٦٠ موضع بحث، و٥٩٦٠ سؤال تعرف إلى السورة، و٦٢١ نشاط ترتيب. هذه أعداد النطاق الكامل في المستوى المتقدم؛ يختلف العدد بحسب النطاق والصعوبة.
- ٢١١ مادة تحريرية: ٧٠ معنى، ٧٣ قولًا، ٥٣ موضوعًا، و١٥ قصة. مع بطاقات السور و١١٩٦٠ كلمة للشبكة وشواهد التجويد المستخرجة وفق العلامات الظاهرة في النص.
- صفحة إدارة المحتوى: إضافة وتعديل ومسودات ونشر محكوم بصلاحية محرر معتمد، واستيراد وتصدير JSON، ومنع الكتابة فوق تحديث أحدث.
- نطاقات القرآن كاملًا وجزء عمّ وقصار السور، وفصل «أسئلة جديدة» عن المراجعة الاختيارية. لا نعد بمحتوى غير محدود: يتوقف السحب عند نفاد النطاق.
- استعادة نسخة احتياطية تدمج سجل منع التكرار، واختبارات تلقائية في GitHub وعند بناء Vercel.

راجع `UPDATE_GUIDE.md` للتعديل والنشر وحدود سجل الضيف والعضوية.

## ما يعمل الآن

- واجهة عربية كاملة باتجاه RTL، بتخطيط متجاوب للهاتف والحاسوب، ووضع للصغار، وبحث وتصنيفات ومفضلة.
- ٢٠ نمطًا للتحديات: ١٨ تعمل بالمحتوى المرفق، ونمطان للاستماع بإعداد المعلّم وإضافة تسجيل محلي. لا يرفع التسجيل إلى أي خدمة.
- نقاط تدريب وسجل إنجازات وهدف يومي على الجهاز. لا تُحتسب نقاط التدريب ضمن الترتيب العام.
- ميدان الحفّاظ: إنشاء مسابقات، تحديد نطاق من سورة وآية إلى سورة وآية، أطوال المقاطع وعدد الأسئلة، إضافة متسابقين، استيراد CSV، سحب المقاطع ومراجعتها واعتمادها، شاشة عرض للمتسابق، لوحة تحكيم بأوزان قابلة للتعديل، مسودة أو اعتماد نهائي باسم المحكّم، لجنة متعددة المحكّمين، سجل عمليات، متوسط درجات وترتيب وتعادل داخل كل مستوى، واعتماد النتائج وتصديرها CSV.
- النص العربي للمصحف كاملًا: ١١٤ سورة و٦٢٣٦ آية. لم تُضمّن ترجمات أو تلاوات خارجية.

## ما جُهّز ويتطلب الربط الحقيقي

- تسجيل حساب بالبريد وكلمة المرور، التفعيل والاستعادة والخروج، بواسطة Firebase Authentication.
- حفظ المسابقات في Firestore من خلال خادم Vercel، والتحقق من صلاحية المنظّم أو المحكّم. كل مسابقة مستقلة في الوصول.
- تحدٍ يومي مصنّف: محاولة واحدة لكل حساب مُفعّل في اليوم بتوقيت UTC. الإجابات الصحيحة وحساب النقاط على الخادم، مع منع احتساب إعادة الإرسال مرتين.
- لوحة منافسة للحسابات التي وافقت على إظهار اسمها ونقاطها.

**رُفعت النسخة إلى [GitHub](https://github.com/omantrooper-crypto/quran_gemaes) ونجح نشرها تلقائيًا على Vercel في ١٧ أكتوبر ٢٠٢٦.** نجحت فحوص المحتوى والاختبارات والبناء في [GitHub Actions](https://github.com/omantrooper-crypto/quran_gemaes/actions/runs/39013224492) للإصدار `64a22a7`. لم يكتمل إعداد Firebase أو اختبار العضويات والمزامنة على مشروع حي بعد. لا يحتوي المستودع مفاتيح مشروع أو حساب خدمة؛ النسخة التفاعلية المفردة تعمل في الوضع المحلي فقط.

## تجربة سريعة

افتح `QuranGames-preview.html` المرفق في متصفح حديث. جرّب «ميدان الحفّاظ ← جرّب بأسماء توضيحية»، ثم افتح أسئلة أحد المتسابقين، ولّد المقاطع، اعتمدها، وانتقل إلى التحكيم. البيانات محفوظة في المتصفح نفسه؛ قد تمنع بعض بيئات المعاينة التخزين المحلي، وعندها تظهر رسالة توضيحية.

لا تستعمل الأسماء التوضيحية كبيانات فعلية. يمكنك إنشاء مسابقة فارغة وإدخال بياناتك. تنزيل نسخة JSON من الإعدادات يحفظ نسخة من البيانات المحلية؛ يمكن استعادة النسخ المنشأة في الإصدار 0.2 من الإعدادات مع دمج سجل الأسئلة.

## تشغيل المشروع

يتطلب Node.js 24 وnpm.

```sh
npm ci
npm run dev
```

البناء والاختبارات:

```sh
npm test
npm run build
npm run preview:file
```

خادم Vite المحلي يعرض الواجهة والتجربة المحلية. مسار `/api/app` يعمل عبر Vercel Functions عند النشر؛ لا يشغّله Vite تلقائيًا. يمكن استخدام Vercel CLI أو Firebase Emulator في بيئة تطوير مجهّزة لاحقًا.

## إعداد Firebase دون تفعيل الفوترة

1. استخدم مشروع Firebase على خطة Spark، دون ربط حساب فوترة.
2. سجّل تطبيق ويب، وانسخ حقول إعداد التطبيق إلى متغيرات `VITE_FIREBASE_*` في `.env.example`، أو في إعدادات Vercel.
3. فعّل Authentication / Email & Password. أضف نطاق Vercel إلى Authorized domains، واضبط رسائل التفعيل والاستعادة.
4. أنشئ قاعدة Cloud Firestore. انشر `firestore.rules` و`firestore.indexes.json` كما هما؛ تمنع الوصول المباشر من المتصفح، لأن البيانات تمر بالخادم الذي يتحقق من الهوية والصلاحيات.
5. جهّز هوية خدمة محدودة الصلاحيات للخادم، مع صلاحيات Firestore اللازمة وقراءة حالة مستخدمي Firebase Auth. خزّن `FIREBASE_PROJECT_ID` و`FIREBASE_CLIENT_EMAIL` و`FIREBASE_PRIVATE_KEY` في متغيرات Vercel السرية فقط.
6. لا تضف المفتاح الخاص إلى GitHub، ولا تستخدم بادئة `VITE_` لأي سر، ولا ترسله في المحادثة.

لا يحتاج هذا المشروع Firebase Storage أو Cloud Functions المدفوعة أو خدمات ذكاء اصطناعي مدفوعة؛ وظائف الخادم موجودة في Vercel. تظل حدود الخطط المجانية وشروطها سارية، ولا توجد ضمانة تشغيل غير محدود.

## النشر القائم وإكمال Firebase

1. المستودع الأساسي هو `omantrooper-crypto/quran_gemaes` والفرع المنشور `main`. الصفحة القديمة محفوظة في سجل Git.
2. المستودع مرتبط بالفعل بمشروع `quran_gemaes` ضمن فريق Vercel `adnan-630c`. التحديثات على `main` تبدأ نشرًا تلقائيًا؛ لا تحتاج استيراد المستودع من جديد.
3. Framework: Vite. Build: `npm run check`. Output: `dist`. Node: 24.x.
4. أضف متغيرات Firebase العامة والسرية، ثم انشر. لا يوجد أي مفتاح داخل هذه الحزمة.
5. اختبر إنشاء حساب وتفعيل البريد، ثم إنشاء مسابقة سحابية صغيرة ومزامنتها من جلسة أخرى، قبل إدخال بيانات المدارس الحقيقية.
6. يسجّل كل محكّم حسابه، وينسخ UID من «رحلة إتقانك». يضيفه المنظّم إلى اللجنة قبل بدء التقييم. يرى المحكّم درجاته وحده، ويرى المنظّم جميع التقييمات.

Vercel Hobby مخصّص للاستخدام الشخصي غير التجاري؛ يجب التحقق من ملاءمته قبل تشغيل المنصة المؤسسية أو التجارية. لم تُفعّل أي خطة مدفوعة أو تجربة ترقية. إن تغيّر نوع الاستخدام أو تجاوزت الموارد الحدود، يلزم إعادة تقييم الاستضافة، ولا ينبغي افتراض مجانية التشغيل العالمي دائمًا.

## البيانات والمحتوى

- مصدر النص العربي: https://quranenc.com ، من ملف Arabic-only في `quran-json@3.1.2`.
- الحزمة القديمة تتضمن ترجمات ذات إشكالات إعادة توزيع؛ لم ننسخ أي ترجمة، ولم نحتفظ بالحزمة كاعتماد للمشروع. اقتصر النقل على النص العربي وأسماء السور وأرقام الآيات.
- ترخيص مجموعة البيانات: CC BY-SA 4.0. النسخة والمصدر والبصمة الرقمية في `public/data/provenance.json`، ونص الترخيص في `public/data/DATA-LICENSE.txt`.
- الاختبارات تؤكد بنية النسخة وبصمتها؛ هذا لا يُعد مراجعة شرعية أو مقابلة نصية مستقلة مع المصحف المطبوع. بنك أسئلة المعاني والتجويد أولي، ويحتاج اعتماد مختص قبل المسابقات الرسمية.
- اختيار مقاطع متساوية في عدد الآيات لا يضمن تساوي الصعوبة أو عدد الكلمات؛ لذلك توجد خطوة مراجعة واعتماد المنظّم.
- التقييم بشري. لا يوجد تحليل صوتي أو تصحيح آلي للتلاوة.
- الخطوط: Noto Sans Arabic وNoto Kufi Arabic، وAmiri Quran للنص القرآني، ترخيص SIL Open Font License 1.1، وتفاصيلها في `public/fonts/OFL.txt`.

## حدود هذه الدفعة

- المحتوى التحريري موسع مع مراجع الآيات، لكنه يحتاج اعتماد مختص قبل المسابقات الرسمية. ألعاب الاستماع تبقى بإعداد المعلم من تسجيله، ولا يوجد بنك تلاوات جاهز في هذه الحزمة.
- شاشة المتسابق وضع عرض في الجلسة نفسها؛ ليست رابطًا عامًا أو شاشة متزامنة على جهاز مستقل.
- الحد لكل مسابقة: ١٠٠ متسابق، ٢٠ مستوى و١٠ محكّمين؛ التخزين الحالي مستند واحد لكل مسابقة، مع التحقق من الإصدار عند الحفظ ومنع الكتابة فوق تحديث أحدث.
- الاعتماد النهائي يقفل تقييم المحكّم، ولا توجد واجهة إعادة فتح أو تظلّم بعد الاعتماد في هذه الدفعة.
- لا توجد بعد بطولات مباشرة، دعوات أصدقاء، رسوم اشتراك، شهادات مصمّمة، تقسيم أدوار إداري متعدد للمدرسة، أو ترجمة الواجهة للغات أخرى.
- قبل الإطلاق العام: مراجعة المحتوى، اختبار حي للصلاحيات والتزامن، مراجعة بيانات الصغار، واختبارات متصفحات فعلية. فُحصت التفاعلات في بيئة DOM دون متصفح بصري في هذه الجلسة.

## البنية

- `src/App.jsx`: المنصة والعضوية والتقدم والمنافسة.
- `src/School.jsx`: المسابقات والتقييم والنتائج.
- `src/GamePlayer.jsx` و`src/questions.mjs`: محركات الألعاب والمحتوى.
- `src/questions.mjs` و`src/history.mjs`: توليد بنك الأسئلة وحجز الجلسات ومنع التكرار.
- `src/ContentManager.jsx` و`src/content.mjs`: إدارة الأسئلة والتحقق من بنية البنك.
- `public/data/editorial-bank.json`: المحتوى التحريري القابل للاستبدال والتحديث.
- `src/domain.mjs`: حدود الحفظ، سحب الأسئلة، الدرجات، الترتيب وCSV.
- `src/cloud.js`: Firebase Auth وعميل API.
- `api/app.js`: خادم الهوية والصلاحيات والمسابقات والمحاولة اليومية.
- `tests/`: اختبارات حدود المقاطع، النص، الدرجات، الأدوار، قفل التقييم، منع تكرار النقاط، وتفاعلات الواجهة.

الـAPI لا يثق بالدرجة الإجمالية أو اسم المحكّم المرسلين من العميل. تُشتق الهوية من Firebase ID token، والاسم المعتمد من قائمة اللجنة، والدرجة من أوزان المسابقة. قواعد Firestore تمنع القراءة والكتابة المباشرة. اختبارات الخادم تستخدم بديلًا اختباريًا لـFirestore؛ لا تُعد اختبار اتصال سحابي حي.
